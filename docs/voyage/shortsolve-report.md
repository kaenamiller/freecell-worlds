# Voyage short-solution solver

## Method and move accounting

`js/shortsolve.js` searches the game's atomic moves and legal supermoves. A whole alternating sequence within `maxMoveSize` costs one manual move. After every manual move, it repeatedly applies the exact `safeFoundationMoves` rule from `js/rules.js`; those foundation moves appear in the returned path with `auto: true` and cost zero manual moves. Other foundation moves cost one. Thus `moves` is the length of the full path and `manualMoves` is the count of moves without `auto: true`.

The search is a bounded, deterministic beam search. It canonicalizes interchangeable free-cell slots and tableau columns for transposition detection, keeps the best layer states, and scores foundation progress, sequence breaks, buried low cards, occupied free cells, and empty columns. Later passes widen the beam and change the score weights when the first pass stalls. A foundation-only endgame is detected with `canFinishWithFoundationOnly`, then played out with safe moves and any necessary manual foundation moves. Every solution is replayed from the original deal: each move must be generated by the rules (or be a safe auto-play), supermove capacity is checked, and the final state must be won. A failed search returns `null` rather than an unchecked or DFS-length par.

The standard bank pass uses **180,000 expanded-state budget, 500-state initial beam, and an 8,000 ms wall guard**. Retry passes use a wider beam and at most a 10,000 ms wall guard. Expansion limits, weight variants, and tie-breaking are deterministic; the wall guard is a safety cutoff, so an unusually loaded host can affect a deal that reaches it. The search is heuristic and does not certify optimality.

A 30-deal repeat at the standard budget reproduced all 30 stored manual counts exactly after the final solver changes.

## Results

The completed ratings file has 5,601 rows, of which 4,524 are `bankable: true`. The 50-deal pilot solved 50/50 with median manual count 38 and median runtime 2.4 seconds; subsequent checkpointed passes covered the whole finished bank.

| Measure | Result |
| --- | ---: |
| Bankable deals processed | 4,524 |
| Solved | 4,523 |
| Success rate | 99.98% |
| Workers | 6 |
| Mean solver runtime per solved deal | 3.15 s |
| Median solver runtime per solved deal | 2.97 s |
| p90 solver runtime per solved deal | 4.73 s |
| Longest recorded runtime | 10.29 s |

| Count | min | p10 | median | p90 | max |
| --- | ---: | ---: | ---: | ---: | ---: |
| Manual moves | 21 | 31 | 38 | 45 | 61 |
| All moves, including safe auto-play | 65 | 75 | 81 | 87 | 100 |

The manual totals are lower than conventional per-card FreeCell counts because a supermove costs one and most safe foundation moves cost zero. The median full path is 81 moves, and the median path contains 44 safe auto-plays. The sole unsolved bankable deal is **159913**; its JSONL counts remain null. A long DFS path exists for it, but using that as par would create the same inflated outlier that motivated this solver. The 10.29-second observed maximum came from a 10,000 ms retry guard under concurrent load; the solver now checks that guard more frequently.

## Longer-budget comparison

On 30 evenly spaced solved bank deals, a 30,000 ms / 750,000-node / 1,000-state beam comparison solved all 30. It improved **25 of 30** baseline counts: the median reduction was **2 manual moves**, and the largest was **7**. This is a comparison to a stronger search, **not an optimality proof**; a few pars may still be several moves above the true shortest solution.

## Reproducing and resuming

```sh
node tools/seedbank/moves.mjs --limit 50 --workers 6 --budget-ms 8000 --nodes 180000
node tools/seedbank/moves.mjs --workers 6 --budget-ms 8000 --nodes 180000
node tools/seedbank/moves.mjs --workers 6 --retry-failed --budget-ms 10000 --nodes 500000 --beam 1000
node tools/seedbank/moves.mjs --compare 30 --workers 6 --budget-ms 30000 --nodes 750000 --beam 1000 --improve
```

The tool snapshots `ratings.jsonl` at launch, selects `bankable: true` rows, skips deal numbers already in `moves.jsonl`, and appends each result immediately. Rerun it after the ratings builder adds rows. `--retry-failed` revisits null results and compacts superseded records at completion. The final JSONL has one row per processed deal:

```json
{"d":1858,"moves":84,"manualMoves":39,"method":"beam","elapsedMs":3802}
```

The example is an actual stored row; `elapsedMs` varies with host load. On timeout, `moves` and `manualMoves` are `null` and `method` is `"unsolved"`.
