# Player accounts

Players can sign in with Google or with an email and password. A signed-in player's stats, settings, current deal, Voyage run and tutorial progress save to their account and sync across devices. Playing without an account works exactly as before.

Infrastructure, configuration, deploys and costs: see [server-infrastructure.md](server-infrastructure.md).

## How it fits together

| Piece | Where | What it does |
| --- | --- | --- |
| Game (static) | `freecellworlds.com` | Unchanged hosting. `js/account.js` (sign-in UI, Turnstile), `js/sync.js` (sync engine) |
| API (Cloudflare Worker) | `api.freecellworlds.com`, code in `server/` | Better Auth under `/api/auth/*`, player data under `/v1/*` |
| Database (Cloudflare D1) | `freecell-worlds` | Users, sessions, save slots, purchases, token ledger, custom themes |
| File storage (Cloudflare R2) | `freecell-worlds-theme-assets` | Custom theme images and music (see [custom-themes.md](custom-themes.md)) |
| Email (Resend) | sends from `mail.freecellworlds.com` | Verification, password reset, account-deletion confirmation |

The session cookie is issued by `api.freecellworlds.com` for the parent domain `freecellworlds.com`, so the browser treats it as same-site and Safari/Firefox tracking protection doesn't block it.

### Identity

- Every account has a random UUID (`user.id`). All player data references that id, never the email.
- The email is a unique login field. Changing it later doesn't orphan any data.
- Google sign-in creates an account, or links to an existing password account with the same email **only if that account confirmed its email**. Unconfirmed password sign-ups are never linked, and the hourly cron deletes them after 24 hours, so nobody can claim someone else's address first.

### Security

- Passwords: scrypt (Better Auth default, native `node:crypto` in Workers), 8–128 characters, checked against Have I Been Pwned (k-anonymity: only a 5-character hash prefix is sent).
- Email + password accounts can't sign in until the email is confirmed.
- Cloudflare Turnstile on sign-up, password sign-in, password reset and resending the confirmation email.
- Rate limits per IP (Better Auth, stored in D1): sign-in 5/min, sign-up 10/hour, reset 3 per 15 min.
- Per-account lockout: 8 wrong passwords within 15 minutes locks that email for 15 minutes, no matter how many IPs the guesses come from (`server/src/data.js`).
- Password reset signs out every session. Account deletion is always confirmed by email.

### Sync rules (`js/sync.js`)

Each synced localStorage key is one save slot with a version number. A device sends the version it last saw; if another device wrote in between, the server answers 409 with its copy.

- **New account:** everything on the device is uploaded.
- **Existing account on a new device:** the account's copy wins. The device's earlier progress is kept in `localStorage['freecellworlds.localBackup']`.
- **Conflict on `stats`, `voyageStats`, `voyageTutorial`:** merged. Counters take the larger value, best time and moves the smaller, and per-theme and per-day maps are combined. If two devices both play offline, counters can come out a little low (each device's total, not their sum), but nothing is lost twice.
- **Conflict on `settings`, `game`, `voyage`:** the device being played wins.
- The account's `game` and `voyage` only replace the local ones while the title screen is open, never mid-deal.
- The game pulls when the tab regains focus and pushes 1.5 s after each save and when the tab is hidden.

## Data model (`server/migrations/`)

- `0001_auth.sql`: Better Auth's tables, generated by `npm run gen:schema`. Regenerate after upgrading `better-auth` or changing plugins.
- `0002_player_data.sql`:
  - `save_slot`: one row per user and key, with `version`.
  - `purchase`: Stripe purchases. `user_id` is set to NULL on account deletion so tax records survive.
  - `token_ledger`: Theme Token balance = `SUM(delta)`.
  - `custom_theme`, `theme_variation`, `theme_asset` and `theme_prompt_check`: a player's generated themes; files live in R2 and are deleted with the account. See [custom-themes.md](custom-themes.md).

Purchases have a read endpoint (`GET /v1/purchases`) and the token balance is in `GET /v1/me`. Nothing writes purchases yet: the Stripe webhook comes later, and `npm run grant` adds tokens by hand meanwhile. Custom themes have their own API, described in [custom-themes.md](custom-themes.md).

## Local development

```sh
cd server
npm install
cp .dev.vars.example .dev.vars
npm run db:migrate:local
npx wrangler dev --port 8787 > /tmp/fcw-api.log 2>&1 &
FCW_API_LOG=/tmp/fcw-api.log npm test     # API end-to-end tests
cd .. && npm run serve                    # game on :8080, talks to :8787
```

Locally, emails are printed to the wrangler log instead of sent, and Turnstile uses Cloudflare's always-pass test keys. If the game runs on a different port, add it to `TRUSTED_ORIGINS` in `.dev.vars`. To check the hourly cleanup, start wrangler with `--test-scheduled` and open `http://localhost:8787/__scheduled?cron=17+*+*+*+*`.

## Production setup checklist

1. **Cloudflare**
   - Production D1 `freecell-worlds` (`8d4f72c3-98ac-4ad1-af49-60b9252b27bb`) and R2 `freecell-worlds-theme-assets` already exist. The id is in `server/wrangler.toml`. Migrations are not applied yet: the manual production workflow applies them, or run `npm run db:migrate`.
   - Turnstile: the widget for `freecellworlds.com` and `staging.freecellworlds.com` is in `CONFIG.turnstileSiteKey` (`0x4AAAAAAFYovaiTyTegTnzy`). Localhost keeps the always-pass test site key. Put the widget **secret** in `TURNSTILE_SECRET_KEY` on each worker.
   - Workers needs the Paid plan: password hashing uses more CPU than the free plan's 10 ms limit. Staging and production also bind a Workflow and Images.
2. **Google Cloud Console** → APIs & Services → Credentials → OAuth client (Web):
   - Client id `895742309264-uprjg6dj8eliu9sr7mf9u866gpfnbuol.apps.googleusercontent.com` is in `GOOGLE_CLIENT_ID` for both `[vars]` and `[env.staging.vars]`. `GET /v1/config` then reports `google: true`, and the game shows Continue with Google.
   - Authorized JavaScript origins include `https://freecellworlds.com`, `https://www.freecellworlds.com`, and `https://staging.freecellworlds.com`.
   - Authorized redirect URIs: `https://api.freecellworlds.com/api/auth/callback/google` and `https://api-staging.freecellworlds.com/api/auth/callback/google`.
   - `GOOGLE_CLIENT_SECRET` is a GitHub environment secret on `staging` and `production`. The API deploy writes it when that secret is set and does not print it.
   - OAuth consent screen: app name, support email, links to `/privacy/` and `/terms/`. Only the default `email`/`profile` scopes are used, so Google's sensitive-scope verification doesn't apply.
3. **Resend:** verify `mail.freecellworlds.com` (SPF/DKIM records go in Cloudflare DNS). `RESEND_API_KEY` is a GitHub environment secret on `staging` and `production`. The API deploy writes it when that secret is set and does not print it. Until the domain is verified, Resend rejects the send and the Worker log has the error.
4. **Email routing:** create `gdpr@freecellworlds.com` (Cloudflare Email Routing). The privacy policy and contact page point to it.
5. **Secrets:**
   ```sh
   npx wrangler secret put BETTER_AUTH_SECRET    # openssl rand -base64 32
   npx wrangler secret put GOOGLE_CLIENT_SECRET
   npx wrangler secret put RESEND_API_KEY
   npx wrangler secret put TURNSTILE_SECRET_KEY
   ```
6. **Deploy:** staging deploys from GitHub Actions on push. Production is a manual workflow run behind the `production` environment. See [server-infrastructure.md](server-infrastructure.md#deploying). From a logged-in machine, `npm run db:migrate` then `npm run deploy`.

## Staging

`api-staging.freecellworlds.com` uses D1 `freecell-worlds-staging` (migrations already applied) and R2 `freecell-worlds-theme-assets-staging`. Theme generation is mocked (`GEN_MOCK=1`). The session cookie is `__Secure-fcw-staging.session_token`, host-only, so it does not collide with production's `__Secure-fcw.session_token` on `Domain=freecellworlds.com`. The game is the static-assets Worker `freecell-worlds-web-staging` at `staging.freecellworlds.com` (deploys from `player-accounts` and `main`). That page calls this API and uses the same Turnstile site key as production. Localhost still calls `:8787` with the test site key. Until `mail.freecellworlds.com` is verified in Resend, open `npx wrangler tail --env staging` to read the confirmation link and the Resend error.

## Later

- **Server-side verification (anti-cheat):** classic deals are numbered and `js/rules.js` is pure, so the Worker could replay a submitted move list to confirm a win. Voyage would need its seeded run engine (`js/voyage/run.js`, charms, bosses) to run headless and deterministically. Only needed if leaderboards are added; start logging move lists when they are.
- **Per-game history:** not stored. Synced totals plus Voyage's last 10 runs (`voyageStats.recent`) cover the stats screens. Add a `game_result` table when leaderboards or a history view need it.
